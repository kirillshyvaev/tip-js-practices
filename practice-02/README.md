## 4. Модель данных и функции

**Поля задачи:**
- `id` — положительное безопасное целое число (`Number.isSafeInteger(id) && id > 0`). Строка `"4"` не преобразуется, а отклоняется.
- `title` — строка; после `trim()` длина от 1 до 100. Сохраняется очищенная строка, пробелы внутри не трогаются.
- `completed` — только `true` или `false`; у новой задачи `false`.
- `priority` — `"low"`, `"medium"` или `"high"`, по умолчанию `"medium"`.

**Файлы:**

| Файл | Назначение |
|---|---|
| `src/data.js` | только данные: `demoTasks`, `variantNumber = 4`, `variantTasks` |
| `src/task-service.js` | девять экспортируемых функций и внутренние помощники `fail`, `done`, `checkId`, `cleanTitle`; без `console.log` и без глобального состояния |
| `src/main.js` | сценарии и вывод; помощник `step(state, label, result)` возвращает новый список при `ok` и прежний — при отказе |
| `checks.js` | готовые 35 проверок, без изменений |
| `my-checks.js` | три собственные проверки на данных варианта |

| Функция | Успех | Ошибка или отсутствие |
|---|---|---|
| `createTask(id, title, priority)` | `{ ok: true, task }`, всегда новый объект | `{ ok: false, error }` |
| `findTaskById(tasks, id)` | объект задачи (`find`, `===`) | `undefined` |
| `getPendingTasks(tasks)` | новый массив невыполненных (`filter`) | — (пустой массив тоже результат) |
| `getTaskTitles(tasks)` | новый массив названий (`map`) | — |
| `getTaskStats(tasks)` | `{ total, completed, pending, progress }`; `completed` считается в `for...of`, `progress` не округляется; для `[]` все нули | — |
| `addTask(tasks, id, title, priority)` | `{ ok: true, tasks: [...tasks, task] }` | ошибки `createTask` или «Задача с id … уже существует» |
| `setTaskCompleted(tasks, id, completed)` | `{ ok: true, tasks }` через `map` и `{ ...task, completed }` | неверный `id`, статус не boolean, задача не найдена |
| `renameTask(tasks, id, title)` | `{ ok: true, tasks }` через `map` и `{ ...task, title }` | неверный `id`, неверное название, задача не найдена |
| `removeTask(tasks, id)` | `{ ok: true, tasks }` через `filter` | неверный `id`, задача не найдена |

Деструктуризация используется в `main.js` (`formatStats`): `const { total, completed, pending, progress } = getTaskStats(tasks)`.

**Почему id не равен индексу:** индекс — это текущая позиция в массиве, после удаления соседей он сдвигается. `id` — постоянный ключ записи. В варианте 4 задача `id = 41` стоит на индексе 3, а после удаления `37` — уже на индексе 2; `variantTasks[41]` вообще `undefined`. Поэтому поиск везде идёт через `find` по `id`.  
**Почему getTaskStats возвращает число, а не строку с процентом:** сводка — это данные для дальнейших сравнений (в проверках и в интерфейсе ПР3). `toFixed(1)` возвращает строку, поэтому округление делается только при выводе в `main.js`.  
**Какие объекты копируются при изменении задачи:** создаются новый массив и новый объект только для изменяемой задачи; остальные объекты переносятся по ссылке. `push`, `splice` и присваивание полям входных объектов не используются. Сохранность исходных данных подтверждает собственная проверка С1.

## 9. Вывод

В ПР1 данные хранились в отдельных переменных, а в ПР2 задача стала объектом, список — массивом объектов, а операции вынесены в модуль `task-service.js`. Функции модуля ничего не выводят и возвращают значения: объект задачи, новый массив, сводку или `{ ok: false, error }`. Поэтому один и тот же модуль без изменений используют `main.js`, `checks.js` и `my-checks.js`, а в ПР3 — обработчики событий.

Неизменность данных подтверждена готовой проверкой 33, снимками `JSON.stringify` для `demoTasks` и `variantTasks` в `main.js` и собственными проверками С1–С3.

Исправленная ошибка — пропущенный `return` в стрелочной функции с фигурными скобками. Самым полезным оказался эксперимент 4: копия массива через spread не копирует объекты внутри. Поэтому при изменении задачи в `map` всегда создаётся новый объект `{ ...task, completed }`, а старый не трогается.
