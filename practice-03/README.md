Отсутствующий элемент и коллекция | `null` и `0` | `Отсутствующий элемент: null`, `Пустая коллекция: 0` | Совпало. `querySelector` без совпадения возвращает `null`; обращение к его свойству дало бы `TypeError`, поэтому результат нужно проверять. `querySelectorAll` всегда возвращает `NodeList` — при отсутствии совпадений пустой, с `length = 0`. |

## Организация кода

| Файл | Что делает |
|---|---|
| `task-service.js` | функции ПР2 без изменений; DOM не использует |
| `task-selectors.js` | `getVisibleTasks(tasks, filter)`: `switch` по фильтру; `pending`/`completed` — `filter` по `completed`, `all` — копия `tasks.slice()`. Всегда новый массив с теми же объектами в том же порядке |
| `task-view.js` | `createTaskElement` собирает `li.task-card[data-task-id]` из `h3.task-title`, `p.task-status`, `p.task-priority` и `div.task-actions` с двумя кнопками (`makeActionButton`, подпись во вложенном `span.action-label`). Весь текст — через `textContent` (`makeElement`). `renderTaskList` — `replaceChildren(...)`. `renderSummary` берёт `getTaskStats(tasks)` и заполняет пять `[data-stat]` в цикле по `Object.entries`. `renderEmptyState` выбирает одно из двух сообщений или скрывает блок |
| `main.js` | состояние (`currentTasks`, `currentFilter`), `renderApp`, `handleTaskListClick`, `handleFilterClick` |

**Где что хранится:** полный список — в `currentTasks`, выбранный фильтр — в `currentFilter` (обе переменные в `main.js`). Видимая выборка нигде не хранится и пересчитывается при каждом `renderApp`. Клики по карточкам ловит один делегированный `handleTaskListClick` на `ul#task-list`, клики по фильтрам — `handleFilterClick` на `#task-filters`. Подписки создаются один раз, вне `renderApp`. Сводка считается функцией ПР2 `getTaskStats(currentTasks)` внутри `renderSummary`, «Показано» — длина видимой выборки.

**Путь одного нажатия «Удалить»:**
1. Клик по `span.action-label` всплывает до `ul#task-list`.
2. `closest("button[data-action]")` находит кнопку; проверяются `contains` и наличие действия в `ACTIONS`.
3. `closest("li[data-task-id]")` находит карточку; `Number(card.dataset.taskId)` проверяется через `Number.isSafeInteger` и `> 0`.
4. Вызывается `removeTask(currentTasks, id)` из ПР2.
5. При `ok` новый массив записывается в `currentTasks`, сообщение очищается, затем `renderApp()` и `restoreTaskFocus(id, action)`; карточки больше нет, поэтому фокус уходит на активный фильтр. При отказе только выводится текст в `#operation-message`, данные не меняются.

|---|---|
| `result.ok` | `true` |
| `result.tasks` (id:completed) | `1:true, 4:true, 7:false, 10:true` |
| `currentTasks` до присваивания | `1:true, 4:false, 7:false, 10:true` |
| `currentTasks === result.tasks` | `false` — новый массив |
| `currentTasks[0] === result.tasks[0]` | `true` — неизменённая задача передана по ссылке |

После продолжения `renderApp()` перерисовал список: у `id 4` статус «Выполнена», сводка 4 / 3 / 1 / 75.0%.

**Отказ для 777 и 4abc.** В панели Elements временно менял `data-task-id` у карточки задачи 4:

| Значение атрибута | Действие | Сообщение | Данные |
|---|---|---|---|
| `777` | «Выполнена» | `Ошибка: задача с id 777 не найдена` | без изменений: 4 / 2 / 2 / 50.0% |
| `777` | «Удалить» | `Ошибка: Задача с id 777 не найдена` (текст из `removeTask`) | без изменений: 4 / 2 / 2 / 50.0% |
| `4abc` | «Выполнена» и «Удалить» | `Ошибка: некорректный идентификатор задачи «4abc»` | без изменений: 4 / 2 / 2 / 50.0% |

`Number("4abc")` даёт `NaN`, поэтому строка не превращается в `4` (а `parseInt` превратил бы). Нажатие на любой фильтр пересоздаёт карточки из настоящего массива `[1, 4, 7, 10]` и очищает сообщение.

**Клавиатура.** `Tab` довёл фокус до «Выполнена» у `id 7` (`aria-pressed="false"`). `Enter` — задача выполнена (4 / 3 / 1 / 75.0%), фокус остался на той же кнопке новой карточки, `aria-pressed="true"`. `Space` — статус вернулся (4 / 2 / 2 / 50.0%), фокус на месте. `Tab` → «Удалить» у `id 7`, `Enter` — задача удалена (`[1, 4, 10]`, 3 / 2 / 1 / 66.7%). Карточки больше нет, и `restoreTaskFocus` перевёл фокус на активный фильтр «Все».

## Вывод

Модуль ПР2 подключён к странице без изменений: `task-service.js` ничего не знает о DOM, интерфейс только вызывает его функции и отображает результат. Карточки собираются через `createElement`, весь текст назначается через `textContent`, поэтому название с тегами остаётся текстом. Все действия с карточками обрабатывает один делегированный обработчик на `ul#task-list`; кнопка находится через `closest`, поэтому клик по вложенному `span` работает так же, как по самой кнопке. `id` из `dataset` — строка, он явно переводится в число и проверяется, поэтому `777`, `4abc`, `0` и пустая строка не портят данные.

Главное: **изменение данных и изменение DOM — разные вещи.** Фильтр меняет только `currentFilter`, полный `currentTasks` остаётся целым, поэтому «Все» возвращает скрытые задачи. Переключение статуса и удаление меняют массив через `setTaskCompleted` и `removeTask`, а DOM затем полностью перерисовывается из массива. Если бы удаление ограничивалось `li.remove()`, задача вернулась бы при следующей отрисовке. Проверки сервиса 35/35 и браузерные 36/36 пройдены, общий сценарий и вариант 4 совпали с ожиданиями методички.
