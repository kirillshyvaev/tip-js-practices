![hello.js в Node.js](./screenshots/task1-hello-node.png)

**Почему отличается `typeof document`.** Объект `document` (DOM) — часть браузерной среды, а не самого языка. Браузер создаёт его для загруженной страницы, поэтому там `"object"`. В Node.js страницы нет и глобального `document` тоже нет. Оператор `typeof` для необъявленного имени не бросает `ReferenceError`, а возвращает `"undefined"`.

## 5. Задание 2. Типы и преобразования

Прогнозы записаны до запуска `node practice-01/js/types.js`. Выражения собраны в массив пар «текст выражения — значение» и выводятся в цикле; строковые значения печатаются через `JSON.stringify`, чтобы были видны кавычки.

```text
 1. "8" + 2           = "82" | тип: string
 2. "8" - 2           = 6 | тип: number
 3. Number("8") + 2   = 10 | тип: number
 4. "12" > "3"        = false | тип: boolean
 5. 12 === "12"       = false | тип: boolean
 6. Number("")        = 0 | тип: number
 7. Number("text")    = NaN | тип: number
 8. Boolean("false")  = true | тип: boolean
 9. typeof null       = "object" | тип: string
10. typeof NaN        = "number" | тип: string
```

![Вывод types.js](./screenshots/task2-types-output.png)

| Выражение | Ожидание до запуска | Фактическое значение | Тип результата | Объяснение |
|---|---|---|---|---|
| `"8" + 2` | `"82"` | `"82"` | `string` | Совпало. При `+` со строкой второй операнд тоже становится строкой — конкатенация. |
| `"8" - 2` | `"82"` или ошибка | `6` | `number` | **Не совпало.** Вычитание определено только для чисел, поэтому строка `"8"` неявно приводится к числу 8. |
| `Number("8") + 2` | `10` | `10` | `number` | Совпало. Строка явно переведена в число до сложения. |
| `"12" > "3"` | `true` | `false` | `boolean` | **Не совпало.** Обе стороны — строки, сравнение лексикографическое: первый символ `"1"` меньше `"3"`, на этом сравнение заканчивается. |
| `12 === "12"` | `false` | `false` | `boolean` | Совпало. Строгое равенство не приводит типы. |
| `Number("")` | `NaN` | `0` | `number` | **Не совпало.** По правилам преобразования пустая строка и строка из пробелов дают `0`. Значит, пустой ввод нужно проверять отдельно. |
| `Number("text")` | `NaN` | `NaN` | `number` | Совпало. Строка не разбирается как число; `NaN` — значение типа `number`. |
| `Boolean("false")` | `true` | `true` | `boolean` | Совпало. `Boolean` смотрит только на пустоту строки, а не на её смысл: любая непустая строка — `true`. |
| `typeof null` | `"null"` | `"object"` | `string` | **Не совпало.** Историческая ошибка языка, сохранённая ради совместимости: `null` — примитив, но `typeof` возвращает `"object"`. |
| `typeof NaN` | `"number"` | `"number"` | `string` | Совпало. «Не число» формально относится к числовому типу. |

В строках 9 и 10 значение выражения — строка с именем типа, поэтому тип самого результата `typeof` всегда `string`.

Ошибся в 4 прогнозах из 10 (`"8" - 2`, сравнение строк, `Number("")`, `typeof null`). Все четыре — неявные правила преобразования типов. Файл одинаково работает в Node.js и в браузере.

## 6. Задания 3 и 4. Проверки

### Задание 3 — `progress.js`

Порядок проверок: тип → `NaN`/`Infinity` → целое → неотрицательное → не больше 1000 → `completedTasks <= totalTasks`. В `errorText` попадает первая найденная причина, и печатается одна строка `Ошибка: ...` без сводки. Случай `0, 0` обрабатывается до вычисления процента, поэтому деления на ноль нет. Статус: по умолчанию «Завершено», при `completedTasks === 0` — «Не начато», при `completedTasks < totalTasks` — «В работе».

Значения меняются в начале файла, затем файл запускается заново. После проверок возвращены данные варианта 4.

### Задание 4 — `plan.js`

Сначала проверяются количества задач по тем же правилам, затем `dailyLimit`: число, целое, от 1 до 1000. Норма проверяется всегда, даже если задач не осталось. При любой ошибке цикл не запускается. План строится циклом `while`: номер дня увеличивается, на день берётся `Math.min(dailyLimit, left)`, остаток уменьшается. В последний день выполняется ровно столько, сколько осталось, и остаток не уходит в минус.

| Проверка | Входные данные | Ожидаемый результат | Фактический результат | Итог |
|---|---|---|---|---|
| Свой вариант | `20`, `11`, `6` | 2 дня: 6 и 3 | День 1: выполнено 6, осталось 3; День 2: выполнено 3, осталось 0; Потребуется дней: 2 | Пройдено |
| Обычный случай | `12`, `5`, `3` | 3 дня, в последний — 1 | 3 / 3 / 1; Потребуется дней: 3 | Пройдено |
| Ровное деление | `10`, `4`, `3` | 2 дня по 3 | 3 / 3; Потребуется дней: 2 | Пройдено |
| Норма равна остатку | `20`, `11`, `9` | 1 день, выполнено 9 | День 1: выполнено 9, осталось 0; Потребуется дней: 1 | Пройдено |
| Норма больше остатка | `5`, `3`, `10` | 1 день, выполнено 2 | День 1: выполнено 2, осталось 0; Потребуется дней: 1 | Пройдено |
| Всё выполнено | `5`, `5`, `2` | 0 дней, цикл не выполняется | `Все задачи уже выполнены`, `Потребуется дней: 0` | Пройдено |
| Задач нет | `0`, `0`, `2` | 0 дней, цикл не выполняется | `Все задачи уже выполнены`, `Потребуется дней: 0` | Пройдено |
| Нулевая норма | `5`, `2`, `0` | Ошибка, цикл не запускается | `Ошибка: дневная норма должна быть от 1 до 1000` | Пройдено |
| Дробная норма | `5`, `2`, `1.5` | Ошибка | `Ошибка: дневная норма должна быть целым числом` | Пройдено |
| Выполнено больше | `5`, `6`, `2` | Ошибка | `Ошибка: некорректное число выполненных задач (больше общего)` | Пройдено |
| Норма строкой | `5`, `2`, `"2"` | Ошибка | `Ошибка: дневная норма должна быть числом, а не строкой` | Пройдено |
| Норма больше 1000 | `5`, `2`, `1001` | Ошибка | `Ошибка: дневная норма должна быть от 1 до 1000` | Пройдено |

![Запуски plan.js](./screenshots/task4-plan-runs.png)

**Почему цикл конечен.** До входа в цикл гарантировано `dailyLimit >= 1`, а `left > 0`, значит `Math.min(dailyLimit, left) >= 1` и каждая итерация уменьшает `left` хотя бы на 1. Без проверки нормы при `dailyLimit = 0` остаток не менялся бы и цикл стал бы бесконечным.

## 7. Задание 5. Отладка

### Исходный результат

```text
Выполнено: 32
Осталось: -24
Контрольная сумма: 6
```

Исключения нет — программа просто печатает неверные числа. В Console браузера вывод такой же.

![debug.js до исправления](./screenshots/task5-before-fix-node.png)

### Ход отладки

1. В `index.html` подключил `./js/debug.js`, в DevTools → **Sources** поставил точку останова на строку `const completedTotal = completedText + additionalText;` и перезагрузил страницу.
2. Выполнение остановилось **перед** этой строкой. В **Scope → Script** видно `plannedText = "8"`, `completedText = "3"`, `additionalText = "2"` — значения в кавычках, то есть строки. В Console: `typeof completedText` → `"string"`, `completedText + additionalText` → `"32"`.
3. **Step over**: `completedTotal = "32"`, тип `string`. Это первая причина — строки склеились. На следующей строке `"8" - "32"` вычитание приводит обе строки к числам, отсюда `-24`.
4. Убрал первую точку и поставил условную в теле цикла с условием `taskNumber === 3`. На остановке `controlSum = 3`, `taskNumber < 4` → `true`. После итерации `taskNumber` станет 4, условие `4 < 4` ложно, и номер 4 не прибавится: 1 + 2 + 3 = 6.
5. Исправил обе причины без подстановки готовых чисел, снял точки останова, проверил в Node.js и в браузере.

![Остановка на строке сложения](./screenshots/debug-breakpoint.png)

| Ошибка | Что наблюдалось | Причина | Исправление | Результат после исправления |
|---|---|---|---|---|
| Обработка количества задач | `Выполнено: 32`, `Осталось: -24` | Исходные данные — строки: `"3" + "2"` = `"32"`, затем `"8" - "32"` → `8 - 32 = -24` | `Number(completedText) + Number(additionalText)`, `Number(plannedText) - completedTotal` | `Выполнено: 5`, `Осталось: 3` |
| Граница цикла | `Контрольная сумма: 6` | Условие `taskNumber < 4` не включает 4 | `taskNumber <= 4` | `Контрольная сумма: 10` |

### Результат после исправления

```text
Выполнено: 5
Осталось: 3
Контрольная сумма: 10
```

## 8. Вывод

- Подготовил окружение (Node.js 24 LTS, npm, Git, Chrome). Один и тот же файл выполняется и в Node.js, и в браузере, но `document` есть только в браузере: DOM предоставляет среда выполнения.
- В задании 2 ошибся в 4 прогнозах из 10, все — на неявных преобразованиях. Вывод: сравнивать через `===`, строки перед вычислениями явно переводить в числа.
- Проверки входных данных выстроены от типа к границам. `typeof value === "number"` недостаточно: `NaN`, `Infinity` и `2.5` тоже числа.
- План по дням построен циклом `while`, обосновано его завершение.
- Освоил точку останова, условную точку, панель Scope и Step over.

**Самая показательная ошибка** — `"8" - "32" = -24`: минус «молча» превращает строки в числа, и программа выдаёт правдоподобное, но неверное число. В отладчике причину выдают кавычки у значений в Scope.
